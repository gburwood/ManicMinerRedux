# SpecForge Core Product Specification 0.1.0-alpha.19

This candidate specification closes the final-delivery governance escape exposed by School Project 10. It succeeds alpha.18; the checkpoint model introduced there remains authoritative except where extended below.

## Final-delivery materiality

A requested final artifact is project material by intent. The path used by a browser, converter, coding agent or other tool for temporary staging does not make a final deliverable non-material.

External scratch, caches, runtime outputs and intermediate research remain permitted working surfaces. Before final delivery, each artifact intended as a durable project result must have a canonical copy at a path classified as project material.

## Guarded managed sessions

Managed interactions begun under alpha.19 carry completion-guard version 1 evidence. Historical interactions created before this capability are not retroactively reclassified and remain valid under their original Core semantics.

A guarded session that reaches material implementation or product-validation completion must remain connected to governance. Repository validation rejects completion evidence with no governed change. A non-terminal governed change may continue through implementation, validation and checkpoint readiness without a final-delivery receipt.

## Managed final delivery

Final delivery is a separate managed transition after checkpoint acceptance has completed the governed change. The finish gate verifies the original session, exact informed proposal approval, completed change, accepted checkpoint authority, project-definition continuity and project-material classification of every final deliverable.

Successful final delivery records a durable completion receipt containing the interaction session, completed change, proposal digest, checkpoint and acceptance identities and SHA-256 identity of each delivered artifact.

A guarded interaction that legitimately ends without a final artifact may record an explicit non-delivery closure with a reason. Silence is not a substitute for either final delivery or explicit closure once completion evidence exists.

## Project definition continuity

The project definition is the durable human-readable intent anchor. Initial creation from an undefined project remains part of managed bootstrap. When a later request changes an already-defined project's authorised outcome, the updated definition must be within the approved governed scope before final delivery.

## Compatibility

The completion guard is prospective. Existing alpha.18 projects and historical managed evidence remain valid and are not silently migrated. Lite Research v0.1.0 continues to add preservation and research requirements without replacing Core governance. Canonical data model remains 0.1.0-alpha.7. Project format remains 1.
